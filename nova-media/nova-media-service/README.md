# nova-media-service

Системный сервис воспроизведения (Этап D ТЗ, компонент 6) — тонкий демон,
который должен был бы держать `/dev/rtkvdec` открытым, принимать команды
воспроизведения через локальный Unix-socket и дёргать `nova-vdec`.

**Статус: NOT IMPLEMENTED в этой сессии.** Причина честная, не отговорка:
без хотя бы одного реально пройденного кадра через `nova-vdec` (что
блокируется отсутствием способа запустить собственное ядро на этом ТВ —
см. блокеры в `NOVA_HARDWARE_4K_DECODER_IMPLEMENTATION.md`) писать сервис
поверх непроверенного API означало бы писать код, который нечем
протестировать даже структурно. `nova-vdec` и `nova-rtk-rpc` — наоборот,
реализованы и компилируются (см. CI), потому что это прямые обёртки над
документированным ABI уже существующего, реального драйвера ядра.

Следующий шаг (не блокирован ничем из вышеперечисленного): написать этот
сервис как тонкий слой над `nova-vdec`, когда появится возможность
протестировать хотя бы `VDEC_IOC_INIT`/`VDEC_IOC_FRAMEINFO` на реально
запущенном ядре — на этом или другом совместимом устройстве.
